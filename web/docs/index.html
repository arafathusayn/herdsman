A skill for coding agents, and a web app to watch them

Run a whole team of coding agents from one conversation.

You talk to one agent, the orchestrator. It runs the rest of the team inside herdr: implementers write the code, reviewers check it, and an integrator combines the work when it ships as one branch. Fixes and reviews go round until each task passes.

Quick start

Two parts work together. The skill runs the team. The herdsman command serves a browser app that shows the team and lets you steer it. You can use the skill alone.

The skill

  1. Install herdr and the coding-agent harnesses you want for each role.

  2. Install the skill for the orchestrator's harness.

    gh skill install arafathusayn/herdsman herdsman --agent <agent> --scope user

  3. Start the orchestrator in a herdr pane and give it the route.

    /herdsman run "tasks: issues 12 and 14; implementers: <harness> <model>; reviewer: <harness> <model>"

The web app

  1. Install the command with Homebrew.

    brew tap arafathusayn/tap
brew trust arafathusayn/tap
brew install --cask arafathusayn/tap/herdsman

  2. Start it on the machine that runs herdr.

    herdsman web --open

  3. Type the 6-digit code that the terminal shows. The browser is now paired with this host.

The team

Every agent runs in its own herdr pane. Each one can use a different harness and a different model: any coding agent that herdr can start and recognize in a pane can take any role.

Adjutant

optional

You talk to it instead of the orchestrator. It asks you the route's questions and relays briefs and answers through a private message channel.

Never writes code, runs tests, commits or pushes.

Orchestrator

The session you talk to. It runs the interview, writes the contracts, launches and watches the agents, forwards review findings and records the results.

Never writes application code and never pushes.

Implementer

one per task

Writes the code and the tests for its task on its own branch, optionally in its own git worktree.

Reviewer

Reviews each task branch and, before a push, the combined result. It reports only P0 and P1 findings.

Changes nothing.

Integrator

when combined

Combines the accepted task branches into one branch, fixes what breaks between them, and is the only agent that pushes.

Checkpointer

helper pane

Asks the orchestrator to save its memory every 15 minutes, and to compact its context past a token limit.

How a route runs

A route is one run of the team over a set of tasks. The orchestrator sleeps between events, so each wake does real work.

  1. 1InterviewTasks, models and rules. It shows a dispatch plan and waits for your go.
  2. 2ContractsA route folder: shared rules and one contract per task.
  3. 3Launchherdr tabs and panes, and a full brief for each implementer.
  4. 4WaitA background waiter exits on the first event.
  5. 5ReviewEach finished task goes to a reviewer: fix or pass.
  6. 6CloseResults recorded, lessons saved to memory.

Fix round. A fix verdict sends the task back to its implementer, and its new report goes back to Wait. A task gets at most three fix rounds; after that, you decide.

Combined tasks. The integrator merges the accepted branches in phases. Only a passing final review of the combined head lets it push.

Pairing and security

A link alone controls nothing. A browser must also prove that it can see the host's terminal.

  1. The link The terminal prints a link with a one-run token after its #. Browsers leave that part out of requests, so proxies and logs never see it.
  2. The code The same terminal shows a 6-digit code. You type it in the browser.
  3. Paired The browser keeps a device secret for this host until the server stops.
  • A code lasts 2 minutes and allows 5 tries. At most 8 pairings wait at one time.
  • Guessing is bounded. After 20 wrong codes in 10 minutes, no new pairing starts until that window moves on.
  • Strong secrets. The link token is 192 bits and the device secret 256 bits, both from the system's random source.
  • Loopback by default. The server listens on 127.0.0.1 unless --host names one other address.
  • No cookies. A request without the header carries no authority, so another site cannot ride on a paired browser.
  • Sandboxed artifacts. HTML pages that agents wrote open in a sandboxed frame, with no access to the app or your pairing.

Skill commands

In the orchestrator session, inside herdr:

/herdsman [subcommand] [options]
Subcommand What it does
run <route request>
or no subcommand		 Runs the full route. The request names the tasks, harnesses, models and rules.
adjutant Attaches this session as the adjutant, your side of the message channel. Options: --name, --orchestrator <pane>, --inbox <root>, --launch.
orchestrator Orchestrates as run does. With --adjutant <name> --name <own-name> --inbox <root>, it enrolls in the message channel first.
message Messages between the adjutant and the orchestrator: status (default), wait, read, release, ack, send, hold, unhold.
checkpoint Manages the checkpointer: start (default), now, probe, status, stop.
status Shows the health of every agent in the current route. Changes nothing.
help Shows the subcommands, options and examples.

Examples

# Two issues, one pull request each
/herdsman run "tasks: issues 12 and 14; implementers: <harness> <model>; reviewer: <harness> <model>"

# Four parts of one change, combined into one pull request
/herdsman run "tasks: four parts of one change, one pull request; implementers: <harness> <model>; integrator: the first implementer that is free; reviewers: two <harness> <model>"

# Check on the team
/herdsman status

Checkpointer

A pane next to the orchestrator that keeps its memory saved and its context small.

/herdsman checkpoint start --every 10 --limit 300k
/herdsman checkpoint now
Option Default Meaning
--pane <id> this session's pane The orchestrator pane to watch
--every <minutes> 15 Time between checkpoints (start only)
--limit <tokens> 250k Compact at or over this context size
--prompt "<text>" the script's default The memory checkpoint prompt
--compact "<command>" /compact The harness's compact command
--side right|down right Where the new pane goes (start only)

Web app

herdsman web serves a browser app that shows and steers the team. Start it on the machine that runs herdr. It prints a link, a pairing code when a browser opens the link, and a QR code for a phone. 

herdsman web --open
TeamA board of every agent in the route, by role or by status.
AgentEach agent's live terminal, its keys and a prompt box. Terminal mode types straight into the pane.
ChecklistThe route's checklist lines.
Run stateThe orchestrator's run log, newest first.
DocsContracts, reports and notes in the route folder.
ChangesThe code each task changed against its base branch, inline or side by side.
ArtifactsHTML pages that agents wrote, such as reports, reviews and plans.
MessagesThe channel between the adjutant and the orchestrator. Read only.

Press ⌘K or Ctrl+K anywhere in the app to open the command palette.

The hosted app

A copy of the app built from main is served at herdsman.arafat.ai (also herdsman.arafat.dev, and the short names h. and herd. on both domains). The server prints a "Hosted app" link that opens it with this host filled in.

The first time the hosted app calls this computer or a private address, the browser asks to access devices on your local network. Allow it, then choose Try again. The link's pairing token waits until the host answers.

Each address is its own browser origin. Hosts and pairings saved on one address do not show on another.

Phones and other hosts

The app can reach any number of hosts: this computer, a LAN or Tailscale address, or a domain in front of a server. Open the Hosts dialog from the server button in the top bar, or paste a host's printed link into it. Each host pairs on its own.

A page served over HTTPS can reach plain-HTTP hosts only on this computer. A phone's 127.0.0.1 is the phone itself. So pick the row that fits where the browser is:

The browser is on Start the server with Then open
This computer herdsman web --open The printed link, or the "Hosted app" link
A phone on your tailnet
recommended for phones		 tailscale serve --bg 7878
herdsman web --public-url https://<machine>.<tailnet>.ts.net 		Scan the QR code. It opens the hosted app with this server filled in.
A device on the same LAN herdsman web --host 192.168.1.20 Scan the QR code. It opens the server's own app over plain HTTP.
Anywhere, behind your proxy herdsman web --allow-host box.example.com https://box.example.com, or add it as a host in the hosted app

Without --public-url, the QR code opens the server's own app, and a line under it says how to get the hosted app.

Web app options

herdsman web [--port 7878] [--host <ip>] [--allow-host <name>]... [--inbox <folder>]
             [--client <url>|none] [--public-url <https url>] [--session <name>]
             [--route <folder>]... [--open] [--no-qr]
Option Default Meaning
--port <n> 7878 Port to listen on; 0 picks a free one
--host <ip> 127.0.0.1 Listen on one other address, such as a LAN or Tailscale IP
--allow-host <name> none Also answer to this host name, such as the domain of a proxy or tunnel (repeatable)
--public-url <https url> none The HTTPS address in front of this server. It is also an allowed host name, and the QR code then opens the hosted app
--client <url> HERDSMAN_CLIENT, else https://herdsman.arafat.ai A hosted copy of the app; none turns the hosted link off
--inbox <folder> HERDSMAN_INBOX The adjutant's private message folder, for the Messages tab (read only)
--route <folder> found from the panes' folders A route folder to show first (repeatable)
--session <name> HERDR_SESSION The herdr session
--open, --no-qr off Open the browser; skip the QR code

Troubleshooting

The hosted app says "Cannot reach This computer"

The browser has not allowed the hosted app to reach devices on your local network yet. Allow its prompt, then choose Try again. If you blocked it before, allow local network access again in the browser's settings for the site.

A host shows as blocked in the hosted app

It is a plain-HTTP address on another machine, which an HTTPS page may not call. Put it behind HTTPS, for example with tailscale serve and --public-url, or open the server's own app at its printed link.

The pairing code does not work

A code lasts 2 minutes and allows 5 tries. Open the printed link again to get a new code. After 20 wrong codes in 10 minutes, new pairings wait until that window moves on.

A paired browser asks for a code again

Device secrets last until the server stops. After a restart, open the new link and pair again.

Hosts I added do not show on another address

Each address, such as herdsman.arafat.ai and h.arafat.dev, is its own browser origin with its own saved hosts. Add the host again there.

Homebrew says the tap is not trusted

Trust it once, then install or upgrade again:

brew trust arafathusayn/tap
