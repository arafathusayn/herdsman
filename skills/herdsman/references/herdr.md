# Herdr: command surface, verified forms, gotchas

The installed binary is the authority: `herdr --help`, then a group without a subcommand (`herdr agent`, `herdr pane`, `herdr tab`). Do not run bare `herdr` (it attaches the TUI). Do not probe mutating commands by omitting arguments (`herdr workspace create` runs with defaults). When the `--help` of a leaf command prints the global help, read the command surface from `herdr api schema --json` or `herdr completion zsh`, because the leaf help is then wrong.

## Verified forms

- Own position: `herdr agent list` shows the caller as `focused:true` with `pane_id`, `tab_id`, `workspace_id`.
- Outside a Herdr pane (a helper script, another session), name the session on each `herdr` command: `herdr --session <name> ...` or `HERDR_SESSION=<name>`. No variable named `HERDR_SOCKET` exists (the socket variable is `HERDR_SOCKET_PATH`). Without a session name the command answers for the default session and shows no agents.
- Tab: `herdr tab create --workspace <w> --cwd <dir> --label "<text>" --no-focus` returns `tab.tab_id` and `root_pane.pane_id`.
- Split: `herdr pane split --pane <id> --direction right|down --cwd <dir> --no-focus` returns `.result.pane.pane_id`. Lettered ids skip letters (pG, pH, pJ, pK, pM). The positional form with `--ratio` printed nothing and still split; use the `--pane` flag form.
- Move inside the same tab is a no-op (`changed:false, reason:"same_tab"`). To re-slot: `herdr pane move <pane> --new-tab --workspace <w> --label tmp --no-focus`, then `herdr pane move <pane> --tab <t> --split right --target-pane <sibling> --no-focus`. The temporary tab closes itself; the pane id stays. A move to another workspace gives the pane a new id: read it from the reply.
- Start Codex: `herdr agent start <name> --kind codex --pane <id> --timeout 90000 -- <codex args>`. Start Claude: `--kind claude ... -- <claude args>`. Success = `interactive_ready:true` in the JSON.
- Prompt: `herdr agent prompt <name or pane> "<text>"`. `--timeout` requires `--wait`. A prompt to a working Codex agent can stay in its composer until you send `tab`, or can interrupt the turn and pause the goal ("Goal paused"); then send `/goal resume` alone ([`codex.md`](codex.md)). A prompt to a working Muse agent is dropped; send it again when the agent is idle. A prompt to a working Claude Code agent is queued ([`claude-code.md`](claude-code.md)). Read the pane after each send, because a send can be lost, queued or interrupt the turn.
- Read: `herdr pane read <id> --lines N` (last N lines), `--source recent-unwrapped` for watcher hashing and before a `grep`, because the pane text wraps in the middle of a word. `herdr agent read` fails on alternate-screen agents (OpenCode); `pane read` works everywhere.
- Close a pane that this route created: `herdr pane close <pane>` (never the orchestrator's own pane).
- Labels: `herdr pane rename <pane> <label>` and `herdr tab rename <tab> <label>`. `pane split` takes no label, so label a new pane with `pane rename` as its own next call. A label is only what Herdr shows: the agent name from `herdr agent start <name>` stays, so prompts, waiters and status specs that use agent names or pane ids keep working after a rename.

## Etiquette (user rule)

- Panes first, then agents, then prompts. One Herdr mutation per Bash call. Never parallel tool calls with two mutations. Reads may run in parallel.
- Pass an explicit pane id or agent name to every call. A call with no pane id acts on the focused pane, which can be the user's.
- A key is an action. Probe an agent with read commands only (`herdr agent get`, `herdr agent read`, `herdr pane read`), because `esc` ends a running turn and any other key lands in the input line. The one exception is the one-key test of a prompt suggestion in an idle Claude Code pane ([`claude-code.md`](claude-code.md), Claude Code panes). Send a key in its own call. After a stray key, read the pane, clear the input line, and tell the agent in one line that the key was not a request.
- Starting an agent, sending a prompt, sending keys and zooming a pane can move the user's keyboard focus into an agent pane, and an unzoom does not move it back. The user's typing then goes to that agent. Before such a call, record the focused tab in an earlier call (`herdr pane list`: the pane with `focused: true`). After it, restore the focus with `herdr tab focus <tab>` as its own next call, because the start, prompt or key call is a mutation and a second mutation in the same call breaks the one-mutation rule. Make the restore the next step after every such call, so that it is not skipped.
- Give every tab and pane, the orchestrator's own included, a short kebab-case label that names the project and the role, right after it is created: tabs `<project>-orchestrator`, `<project>-implementers`, `<project>-reviewers`; panes `orchestrator`, `im-<task>`, `reviewer-<harness>`. The one exception is the `checkpointer` pane: its label stays exact, because the checkpoint actions find the pane by that label ([`checkpointer.md`](checkpointer.md)). Reason: a tab number or a shell title does not say which project or agent a tab or pane holds, and the user then has to ask for the names.
- Four implementers get a 2 by 2 grid in their own tab; the reviewers get their own tab. A 134x51 orchestrator pane split 2 by 2 gives 67x25 implementer panes; sibling splits of the orchestrator pane are too narrow (agent names vanished at 34 columns).
- The route launch (tab, panes, Docker, contract files) waits for the user's go on the dispatch plan.

## Gotchas

- A Herdr call that fails in an output filter (for example `jq`), times out or is rejected by the harness can still have run. List the tabs, panes and agents before a retry, because a retry makes a duplicate. Put parentheses around an alternative in a `jq` object (`{tab: (.a // .b)}`), because the form without them does not compile.
- A `herdr agent start` that the harness rejected can leave the pane with a stuck name (`agent_launch_pending`); `agent rename --clear`, the same name (`agent_name_taken`) and a fresh name (`agent_pane_busy`, "not an available shell") all fail. Remedy: close that pane and split a fresh one.
- Agent names must match `^[a-z][a-z0-9_-]{0,31}$` (`invalid_agent_name` otherwise) and are global across workspaces: `agent_name_taken` means another workspace's route may hold the name. Use route-specific names and keep display names in contracts.
- Read a pane before you reuse it: the user may have started another session there. `herdr agent prompt <pane id> "/quit"` reaches an agent that has no name.
- `herdr pane list | grep <label>` also matches panes whose text holds the label; filter the JSON by its `label` field.
- Every herdr call must be a plain top-level command. Calls inside `for` loops with `set --`, or with long `${VAR//x/y}` substitutions, exit 1 with no output.
- Herdr's agent state is unreliable for Codex: it may say `working` at the prompt and `idle` mid-task. Truth is the pane text: an active Codex shows `• Working (Ns • esc to interrupt)` or `Pursuing goal (Nm)`; the `› Ask Codex to do anything` line is always present.
- Names vanish from `herdr agent list` for Codex agents in narrow panes, after a `/new`, after a goal ends, and after the user changes the model in the pane. `herdr agent rename <pane> <name>` registers the name again. Check `herdr agent list` after each `/new`; on `agent_not_found`, rename and send the same prompt again. Right after `agent start`, an agent can show no name or no kind for a few seconds: read `herdr agent get` again before you treat `agent_not_ready` as blocked.
- Herdr reports an agent `idle` while a long foreground command runs; read the screen before treating it as stalled.
- `agent_status: blocked` means Herdr recognised an approval UI; `unknown` does not prove completion.
- Herdr has no stop command. To quit an agent, send its own exit command, wait for the shell prompt, then start again; flags apply per process. Use `/exit` for Claude Code ([`claude-code.md`](claude-code.md)) and `/quit`, then Enter, for Codex ([`codex.md`](codex.md)). Do not use ctrl+c or ctrl+d: they do not end the session. Before a start in a reused pane, read the pane until it shows a bare shell prompt with no stray text in the input, because stray text corrupts the start command.
- After any restart (of the session, the Herdr server or the machine) or a harness configuration change, read every pane: agents, waiters and watchers attached to the old server are gone, and sessions that kept running keep the tools and hooks they started with. Re-arm the waiter, the pull request watcher and the checkpointer. Relaunch each agent that exited with a full brief that tells it to check its existing work first. Send the current job again from the route file only to an agent whose pane shows the job was interrupted (a shell prompt, or an idle input with no finished report); an agent still working keeps its job, and a second copy can repeat its work or its mutations. A restored pane keeps only its folder and label. After a reboot, also check the container runtime and the credential store.
- A server stop or restart ends every pane, the orchestrator's own pane too. Ask the user first, and give the pane and agent counts. List the foreground processes of the panes: an idle shell loses nothing, but a running job ends. Write the route state to memory and to the route file first. Pane ids belong to the old server, so find panes by label after it.
- `herdr channel set` and `herdr update --handoff` refuse to run inside a Herdr pane; the user runs them outside. The handoff keeps panes and agents alive. When it does nothing (the installed binary is current, but the server is old), the user stops the server and starts `herdr` again from a GUI terminal, because a server that a pane starts inherits that pane's environment.
- `/goal` is a feature of the harness, not of Herdr. Codex and Claude Code take it. Muse and OpenCode take plain prompts.
- `herdr pane send-keys` takes key names only; text such as `/new` fails with "unsupported key". Send text with `herdr agent prompt <name> "<text>"`.
- `herdr agent prompt` answers `agent_blocked` while Codex shows a queued follow-up question; clear it with `pane send-keys <pane> alt+up` then `'ctrl+]'` (see [`codex.md`](codex.md)). Key names: `alt+up`, `ctrl+]`, `esc`, `enter`. `pane send-text` and `pane run` (text plus Enter) bypass the agent state check; use them only when the agent commands refuse.
- A zoomed pane hides every other pane of its tab, the checkpointer side pane included, so the user cannot see it. `herdr pane layout --pane <id>` shows `"zoomed": true`; `herdr pane zoom <pane>` toggles it back. After notice handling or any zoom, check that the orchestrator's tab is not left zoomed, and restore the user's focus (see Etiquette).
- A new pane's shell can open with a startup question (for example a shell framework's "update? [Y/n]"), and the first `pane run` text becomes its answer: the command never runs, or runs without its environment prefix. Read the pane after every `pane run` in a new pane and run the command again on a clean prompt. The same start-up (a hook, a question or a self-update) can swallow the first `herdr agent start`, which then answers `agent_pane_busy` or times out: read the pane, wait for the shell prompt, and run the same start again. Before labelling a new pane `checkpointer`, check that no other pane of the workspace, the orchestrator's own included, already carries that label: a stale label makes the checkpointer lookup by label ambiguous.
- A `grep -o '"type":...'` on a prompt result hides errors: the error JSON has no `type`. Print the result with `head -c 300` instead and look for `agent_prompted`.
- `herdr agent wait` and `herdr agent prompt --wait` do not track turns. They can return at once with no output, when an earlier turn ends, or when a new prompt interrupts a turn. Treat the result as a hint. Confirm with `herdr agent get`, the pane and the report file, and arm the wait again after you send a correction to a working agent.
- `herdr agent wait <name> --timeout N` ends with `{"error":{"code":"timeout",...}}` on exit 1 when the agent stays busy; a `grep` for `agent_status` then prints nothing ("No matches found"). A `--wait` timeout on a prompt bounds only the call: do not send the prompt again before you read the pane. A long Muse turn outlasts a one-hour wait; rely on the waiter (REPORT-UPDATED, see [`watchers.md`](watchers.md)) instead of long agent waits.
- `herdr pane wait-output --match` also matches old scrollback, so it can end at once. Confirm a result with a fact outside the pane text (a file, a version or a commit id).
- A prompt can sit unsent in an idle agent's input (the line shows `[Pasted text #N]`): send one `enter`. Read the pane before any `enter`, and send it only when your own text is in the input of an idle agent.
- Prompt text goes through the shell. Put no apostrophe inside single quotes, and no backtick or `$` inside double quotes, because the shell runs a backtick as a command and expands `$`. For a long text, write a file with the file tools and send a short prompt that names the file. Run `git --no-pager` in a pane, because a pager blocks the pane.
- A test or a tool that runs in an agent pane and calls Herdr inherits the pane's `HERDR_*` variables and reaches the user's own session. See the Live tests rule in [`contracts.md`](contracts.md).
- `herdr agent start` takes no environment, a pane made with `pane split` does not get the workspace environment, and a restored pane keeps only its folder and label. Set a variable on the process itself (an `env` prefix in the launch command), and check it with `ps eww <pid>` before a run.
